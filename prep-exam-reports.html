Prep Exam Reports

🧪 Prep Exam Reports — a rehearsal, not the report card

A prep exam is a prototype of the school examination, sat to test how ready your students are. Everything on this page comes from the prep ledger, which is separate from the report card. No score on this page can be pushed to, or printed on, a report card — the database refuses it, not just this screen.

📝 Prep Test Reports — Once per term

Generate a standalone Prep Exam sheet for every student, separately from the terminal report. Use the single CBT purpose Prep Assessment; its report destination is chosen separately and may be CA1, CA2, Prep, or a legacy mid-term CA/Test column. Every generated student row has an individual print-ready sheet, with a class-wide print option.

Workflow: create a CBT with the purpose Prep Exam (rehearsal), then push its verified results to the PREP reportlts from CBT → Bulk Push to Report Cards, then generate here. You do not need a column literally named “Prep”. Generation still creates a roster sheet if scores have not been pushed; those entries are clearly marked “No score” rather than treated as zero marks.

🎯 Readiness summary

A rehearsal is only useful if it tells you who to help. This summary groups the class by readiness and names the learners in each group, so a teacher can act before the school examination rather than after it.

Generate the prep reports to see readiness.

⚙️ What the prep report prints — positions

Decide whether prep reports show a position in class. This switch is separate from the terminal report card, so a school can rank at the end of term and not at prep — which is what many primary schools do. Marks are never changed; only what is printed changes.

Press Load current setting to see and change it.

How it stays in sync with terminal reports

  • One assessment purpose, flexible destination: Prep CA and Prep Test are normalized as one Prep Assessment purpose. Legacy ca/test exams and rehearsal purposes are recognised. The report-card destination is not another assessment type.
  • Same source, no hidden magic label: The Prep sheet reads only the prep ledger (prep_scores) and nothing elseolumns from report_scores. A literal column named Prep is optional. If a score is not pushed, the roster still generates with a clear “No score” state.
  • No conflict: prep_report_cards has unique(student_id_ref, class, term, session) separate from report_cards (report_cards is terminal). Same student can have both for same term.
  • Published flag: Tutors generate (published=false) first to preview, then publish. Students/parents only see published via get_prep_report + RLS is_parent_of.
