Midterm Reports

📝 Midterm Test Reports — Once per term

Generate a Midterm sheet separately from the terminal report. Use the single CBT purpose Mid-term Assessment; its report destination is chosen separately and may be CA1, CA2, Midterm, or a legacy mid-term CA/Test column. The report uses only scores recorded in the matching mid-term columns in report_scores.

Workflow: create a Mid-term Assessment CBT, choose CA1/CA2/Midterm as its report destination, push its verified results from CBT → Bulk Push to Report Cards, then generate here. You do not need a column literally named “Midterm”. Generation still creates a roster sheet if scores have not been pushed; those entries are clearly marked “No score” rather than treated as zero marks.

How it stays in sync with terminal reports

  • One assessment purpose, flexible destination: Mid-term CA and Mid-term Test are normalized as one Mid-term Assessment purpose. Legacy ca/test exams and columns named Midterm, Mid-term Test/CA, CA1 or CA2 are recognized. The report-card destination is not another assessment type.
  • Same source, no hidden magic label: The Midterm sheet reads only matching Midterm/CA1/CA2 score columns from report_scores. A literal column named Midterm is optional. If a score is not pushed, the roster still generates with a clear “No score” state.
  • No conflict: midterm_report_cards has unique(student_id_ref, class, term, session) separate from report_cards (report_cards is terminal). Same student can have both for same term.
  • Published flag: Tutors generate (published=false) first to preview, then publish. Students/parents only see published via get_midterm_report + RLS is_parent_of.
