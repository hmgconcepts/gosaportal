# School Connect V5.8 — Deletion Integrity, ID Formats and Free-Tier Efficiency

## Deleted records reappearing

Three causes were fixed: the complete schema reinserted default lookups whenever it
was rerun; old table HTML could be shown indefinitely after a failed refresh; and
several custom pages treated a zero-row RLS delete as success. Defaults now run only
on a genuinely empty first installation and are recorded in `sc_install_state`.
Deletes return affected IDs, are re-queried for verification, invalidate session
caches and stale fallback HTML expires after one minute. Academic Setup also rejects
out-of-order refresh responses. The executed SQL test deletes `2024/2025`, reruns the
complete schema and proves it stays deleted.

The demo seed intentionally restores demo data when manually/periodically rerun;
never run it in production.

## Admission and staff IDs

Browser generation using stale `config.js` acronyms was removed. PostgreSQL is now
the sole authority and reads current `school_settings`: prefix, format, starting
number, year inclusion, staff prefix and staff middle segment. Advisory locks and
unique indexes protect concurrent registration. The executed test produced exactly:

- `GOSA/2026/0001`
- `GOSA-STF-00001`

Existing IDs are not renamed automatically; only new records use the saved format.
Settings now calculates the actual next sequence from existing records.

## Supabase free-tier efficiency

The platform remains external-link-only for media. Operational UI no longer stores
uploaded signature files or Base64 images. Certificate signatures use Drive/external
URLs; the drawing pad downloads a local PNG for the administrator to place on Drive.
A browser guard and PostgreSQL trigger reject new embedded `data:`/Base64 media.
CSV/JSON files are parsed locally; source files are not stored. The generator logo is
embedded only in the static deployment ZIP, not Supabase.

`data_retention_settings`, `storage_health()` and `retention_candidates()` power the
new Storage Efficiency Centre: configurable planning quota, warning/critical levels,
per-table retention periods, database usage, embedded-media audit and eligible-row
analysis. Purge remains deliberate: export portable JSON first, select a table, then
confirm. No automatic destructive cron is enabled.

## Deployment

Back up Supabase, run the full updated `database/complete-schema.sql`, deploy every
file and hard-refresh. Do not run versioned SQL afterward. Frontend-only deployment
cannot install the corrected ID triggers, bootstrap state, retention RPCs or media
guard.
