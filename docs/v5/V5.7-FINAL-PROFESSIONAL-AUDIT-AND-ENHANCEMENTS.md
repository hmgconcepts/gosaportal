# School Connect V5.7 — Final Professional Audit and Enhancements

## Scope reviewed

The generator, GOSA deployment and prospective-client demo were reviewed as one cumulative platform. The audit covered current live public surfaces, repository/runtime parity, SQL, public forms, document outputs, report workflow, role navigation, registered-value fields, storage behaviour, PWA caching and generator ZIP output.

The live sites are static Vercel deployments backed by their repository/Supabase deployments. This release updates the deployable files; GitHub/Vercel/Supabase still require an authenticated upload/deployment by the owner.

## Material gaps diagnosed and repaired

### Institutional signatures

The platform previously had a principal signature setting while the examination officer was device-local on the Entrance page and proprietor identity was not centrally managed. V5.7 adds school-wide principal, proprietor and examination-officer names/signature links. Google Drive links are normalized. “Remove white background” performs transient browser pixel processing when CORS permits and uses print-safe blend/contrast fallback otherwise. Only links/flags are stored—no image file is uploaded to Supabase Storage.

Relevant outputs now use the appropriate role: principal on report cards, proprietor on owner-authorized financial documents, examination officer on entrance/exam outputs, and a selectable signatory on custom documents.

### Public examination registration

The former “Generate Public Registration Link” attempted to insert campaign-only columns into `exam_registrations` that did not exist, pointed to the wrong public page, exposed controls on a public surface, and had no edit/delete lifecycle. V5.7 introduces `exam_registration_links`, safe public getter/submission RPCs and a leadership-only campaign editor.

A campaign can define title, introduction, allowed exam types, registered session/term, deadline, exam date, venue, fees, requirements, instructions, contacts, consent/success text and hidden optional fields. Links can be copied, edited, activated/deactivated, deleted and exported. Deleting a link retains historical submissions but severs the public campaign relationship. Full candidate payloads export to CSV.

### Custom Document Builder

The builder now supports preset or free-text document type, reference, registered student/class/term/session, recipient, selected institutional signatory and additional placeholders. The erroneous document type beneath the principal signature has been removed; only signatory name and designation appear there.

Supported placeholders include `[NAME]`, `[CLASS]`, `[TERM]`, `[SESSION]`, `[DATE]`, `[REFERENCE]`, `[SCHOOL]`, `[PRINCIPAL]`, `[PROPRIETOR]` and `[EXAM_OFFICER]`.

### Performance-based report comments

`report_comment_bands` stores educator-approved overall-percentage ranges and class-teacher/principal comments. The Report Comments page now includes a bulk comment centre that calculates overall performance only from official `report_subject_totals`, ranks the class, expands pedagogical tokens and upserts comments for a selected class/term/session.

Manual comments are marked `comment_locked=true` and are preserved by default. An explicit overwrite confirmation is required. Demo bands cover Outstanding, Very Good, Good, Satisfactory, Developing and Priority Support, with intervention-focused wording rather than discouraging labels.

### Proprietor, principal, head teacher and bursar separation

The proprietor remains a distinct profile role and receives owner-level governance. Principal and head-teacher navigation is operational/academic rather than ownership-level. The bursar is restricted to finance-relevant navigation. Site-license and role-status writes are owner-only; school-wide settings are leadership-managed.

The previous navigation defects included broad admin bypass for bursar/principal, stale local permission maps surviving a database reset, direct-page bypass, raw/normalized module-ID mismatches and an owner access manager visible to unrelated management roles. These paths were corrected and regression-tested across eight roles.

### Registered-value dropdowns

CRUD form definitions are normalized at runtime. Text fields representing registered class, subject, department, arm, campus, teacher, term or session are converted to relational/lookup dropdowns while preserving the stored text value expected by existing tables. This applies to explicit and generic modules.

## Security and data-quality improvements

- Anonymous public registration writes go through `submit_exam_registration`; direct anonymous table access is not required.
- Public campaign reads return only approved campaign fields.
- Leadership authorization is checked in PostgreSQL for campaign deletion.
- Owner and school-leader helper functions provide explicit policy boundaries.
- Manual report comments cannot be silently overwritten.
- Public campaigns close automatically at their deadline.
- Signature files are not stored; only external links and display flags are persisted.
- Registered exam identity, CBT server grading, teacher subject/class ownership and family-safe RLS remain cumulative.

## Deployment requirement

Back up Supabase and run the updated `database/complete-schema.sql`, then deploy every repository file and hard-refresh. Frontend-only deployment cannot install the new tables, columns, RLS policies or RPCs. The complete schema remains the only production SQL. Demo users/seed remain the only demo-only exceptions.
